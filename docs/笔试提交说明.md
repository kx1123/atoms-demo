# Atoms Demo 笔试提交说明

作者：Jiakx1123

在线测试地址：[Atoms 对话式应用工作台](https://atoms.39.108.96.233.sslip.io)

GitHub 源码地址：[kx1123/atoms-demo](https://github.com/kx1123/atoms-demo)

Atoms Demo 是一个通过自然语言创建和迭代网页应用的工作台。用户输入需求后，服务端调用真实模型生成 HTML、CSS 和 JavaScript，在隔离区域运行；后续修改保存为新版本，可预览历史并恢复。

## 如何体验

无需注册，打开在线地址即可使用。建议先生成一个小型应用，体验完整流程：

1. 输入“做一个中文计数器，包含加一、减一和重置按钮，保存计数”。
2. 等待生成完成，在右侧实际点击按钮。
3. 继续输入“保留已有功能，增加一个加十按钮”。
4. 查看新增功能，再打开版本历史，预览或恢复之前的代码。
5. 刷新页面，确认项目、对话、版本和已保存的应用数据保留。

首页另提供标注为“非 AI 生成”的待办交互示例，方便快速体验预览、代码查看和数据保存。自由需求生成使用真实模型接口，生成耗时随模型响应和需求复杂度变化。

## 实现思路与技术取舍

采用 TypeScript、Next.js 和 React，实现页面与服务端接口；使用 SQLite 保存项目、对话、运行任务、不可变代码版本及应用数据；Docker Compose 管理独立的应用、网关、网络和持久化数据卷。

首版聚焦无需构建、无需外部依赖的单页前端应用。这个范围可以把主要投入用于生成、运行、修改和恢复的完整体验，同时减少依赖安装、服务启动和运行环境差异带来的不确定性。没有在首版引入任意 npm 工程或后端服务生成。

生成流程使用明确的状态机：准备上下文、模型调用、输出解析、HTML 结构和 JavaScript 语法检查、保存版本。检查失败时最多自动修复一次。流式读取模型响应，SSE 向浏览器传递等待时长、接收字符数及实际执行状态；生成与修复分别计时，并区分总时限与有效输出空闲时限。失败时保留上一版，客户端断线后可以查询任务结果。

模型地址、名称和密钥均由运行环境变量配置。公开源码仅包含占位示例，真实 env 不进入代码、Docker 镜像或源码上传包。

## 亮点设计

版本历史与生成任务关联，方便理解每次修改的来源。恢复旧代码会生成新版本，避免覆盖原有历史；应用状态与代码版本分开保存，允许用户回退界面实现而保留当前数据。

生成网页通过受限的 `window.atoms.get/set` 存储接口保存 JSON 数据，不依赖 iframe 的浏览器本地存储。宿主校验预览窗口与消息令牌后写入数据库，容器重建后仍能恢复。

界面将对话与预览放在独立滚动区域。生成下一版时继续展示上一版；用户可以在等待期间操作已有应用，并在完成后查看新结果。

## 验证结果

已通过 19 项自动化测试，覆盖归属隔离、请求去重、失败保留旧版、基准版本保护、恢复追加版本、重启恢复、HTML 检查、有限自动修复、调用限制，以及流式解析、连接截断、空闲超时、总超时与修复独立计时。生产构建通过。

上线后完成以下真实浏览器验收：首次生成“小小进步”计数器，点击后计数为 2；对话新增加十按钮，保留原计数并操作至 12；恢复旧代码后保留历史并追加为版本 3；重建应用和网关容器后，3 个版本、2 个完成任务及计数 12 仍然保留。

公网 API 另验证了项目保存、版本恢复、匿名会话隔离和跨站写入拦截。自动化模型流程测试使用模拟服务响应；上述浏览器生成与修改验收调用了真实模型。

## 当前边界

支持原生 HTML、CSS 和 JavaScript 单页前端应用，不包含任意依赖安装、后端服务生成、多人协作和应用账号系统。静态检查通过与预览加载成功不等于全部业务逻辑正确，复杂需求仍需实际操作验证。

历史恢复只恢复代码，不回滚应用数据；历史预览中的操作不会写入数据库。下载的独立 HTML 包含当时的数据快照，离线修改不会在刷新后持久化。

匿名会话清理 Cookie 后无法从新会话打开原项目。当前未实现跨设备登录与项目迁移。

## 继续投入的优先级

1. 增加隔离的浏览器交互检查，将可复现的运行与交互错误反馈给修复流程，降低“页面已加载但功能不正确”的比例。
2. 支持多文件前端工程和受控依赖列表，增加编译检查、运行日志及细粒度代码差异查看。
3. 完善长任务取消、断点恢复和成本观测，再评估队列及多实例存储迁移。
4. 根据真实使用需求补充跨设备项目访问、可分享预览与协作能力。
